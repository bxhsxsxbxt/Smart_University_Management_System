#  SAD Project – University Platform (Phase 1)

##  عنوان پروژه

**SAD Project – University Microservices Platform**
یک سامانه دانشگاهی مبتنی بر معماری میکروسرویس با هدف مدیریت ورود، کاربران، درس‌ها، ثبت‌نام، نمرات و سرویس‌های کمکی از طریق یک API Gateway.

---

##  توضیحات پروژه

هدف این فاز پروژه، درک دقیق این است که **چه چیزی می‌سازیم** و **چرا معماری میکروسرویس برای آن مناسب است**.

ما در حال طراحی یک سامانه دانشگاهی هستیم که شامل سرویس‌هایی مثل Auth، User Management، Courses، Grades و Notification خواهد بود.
به‌دلیل پیچیدگی دامنه، حجم کاربران، نیاز به توسعهٔ مستقل سرویس‌ها و مقیاس‌پذیری، معماری **Microservices** بهترین گزینه است.
در این معماری، هر سرویس به صورت مستقل توسعه، تست و دیپلوی می‌شود و خطای یک سرویس باعث از کار افتادن کل سیستم نمی‌شود. همچنین امکان رشد مرحله‌ای و انعطاف‌پذیری بالا فراهم است.

---

##  تصمیمات اولیهٔ معماری (Phase 1)

* معماری کلان: **Microservices + API Gateway**
* ارتباط بین سرویس‌ها: REST (در فازهای بعدی MQ اضافه می‌شود)
* احراز هویت: JWT در سرویس Auth
* دیتابیس هر سرویس: مستقل – شروع با PostgreSQL
* اجرای سرویس‌ها: Docker و docker-compose
* مستندسازی API: Swagger/OpenAPI
* ساختار داخلی سرویس‌ها: لایه‌های API، Service، Repository، Model
* امنیت: تمام درخواست‌های خارجی فقط از طریق Gateway
* قابلیت توسعه: امکان افزودن/حذف سرویس بدون وابستگی به دیگر سرویس‌ها

> **دیگرام C4** در بخش ویکی مخزن قرار دارد.

##  نصب و راه‌اندازی

### پیش‌نیازها

* Python 3.10+
* Docker & Docker Compose
* Git
* PostgreSQL یا استفاده از نسخه dockerized

### مراحل نصب

```bash
git clone <repo-url>
cd <project>
docker-compose up --build
```

### اجرای سرویس Auth (مثال)

```bash
cd auth-service
uvicorn main:app --reload
```

##  نحوه استفاده (Phase 1)

پس از اجرای docker-compose:

* API Gateway روی پورت مشخص‌شده (مثلاً 8000)
* سرویس Auth روی پورت (مثلاً 8001)

برای تست API:

```
http://localhost:<port>/docs
```

مثلاً سرویس Auth:

```
http://localhost:8001/docs
```
